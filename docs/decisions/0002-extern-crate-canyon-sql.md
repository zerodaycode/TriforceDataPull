# 0002 - Keep `extern crate canyon_sql`

- Status: Accepted
- Date: 2026-10-16

## Context
With Canyon-SQL `develop` (`1c81b3b`) the build fails with:

```
error[E0433]: cannot find `canyon_sql` in the crate root
```

Most of the code generated by the Canyon macros uses `canyon_sql::...`, but 4 places use `crate::canyon_sql::...`. `crate::` is our crate, so the path only exists if our crate root has the crate declared. The book doesn't mention it.

| File (Canyon-SQL `develop`) | Generated by |
|---|---|
| `canyon_macros/src/query_operations/read/find_all.rs:34` | `Crud` / `Read` (`find_all`) |
| `canyon_macros/src/query_operations/read/find_all.rs:58` | `Crud` / `Read` (`find_all_with`) |
| `canyon_macros/src/query_operations/read/foreign_key.rs:439` | foreign key lookups |
| `canyon_macros/src/canyon_mapper_macro.rs:78` | `CanyonMapper` |

## Decision
Keep this at the top of `src/main.rs`:

```rust
extern crate canyon_sql;
```

## Consequences
- Good: one line, everything compiles.
- Bad: it's a workaround. Remove it when Canyon changes those paths to `::canyon_sql::` (fix to report upstream, see [ROADMAP](../../ROADMAP.md)).
